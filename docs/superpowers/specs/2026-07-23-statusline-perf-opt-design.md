# statusline 극한 최적화 설계

## 한 줄 정의

매 렌더마다 실행되는 `statusline.sh`의 벽시계 시간을, POSIX sh 계약과 표시 기능을 그대로 유지한 채 최소화한다.

## 목표

- per-render 벽시계 시간을 현재 실측 기준점에서 유의미하게 줄인다.
- 표시 항목, 색, 막대, 브랜치 표시가 모든 상태에서 지금과 동일하다. 기능 손실은 없다.
- 모든 셸 스크립트는 POSIX sh를 유지한다.
- 기존 테스트가 모두 통과하고, 최적화가 도입하는 새 동작에는 회귀 테스트를 추가한다.

## 비목표

- 렌더 로직을 sh가 아닌 다른 언어로 다시 쓰지 않는다.
- 표시 항목을 늘리거나 레이아웃을 바꾸지 않는다.
- 비용 집계(`refresh-cost.sh`)의 백그라운드 구조는 바꾸지 않는다.

## 현재 상태 실측 (기준점)

로컬에서 fixture JSON을 반복 실행해 측정했다.

- git 저장소를 현재 디렉터리로 둔 렌더 30회: 총 4.690초, 렌더 1회 약 156ms.
- `/tmp`(비저장소)를 현재 디렉터리로 둔 렌더 20회: 총 2.514초, 렌더 1회 약 125ms.

렌더 1회의 시간 기여는 다음과 같이 분해됐다. 시간이 큰 순서로 적는다.

- 축약 스크립트(`shorten.sh`)를 별도 sh 프로세스로 매 렌더 두 번(경로, 브랜치) 띄운다. 회당 약 15ms로 두 번이면 약 30ms다. 프로세스 시작 비용이 로직 자체보다 크다.
- `date`를 여러 곳에서 각자 호출한다. 약 10회로 합계 약 20ms다.
- Claude 계정 이메일을 얻으려고 `~/.claude.json`(약 258KB)을 매 렌더 awk로 스캔한다. 약 9ms다.
- git 브랜치를 `git rev-parse`로 조회한다. 약 6ms이며 큰 저장소에서는 더 커진다.
- `format_model`이 모델 문자열을 sed 파이프라인으로 파싱한다. 조건에 따라 sed를 최대 네 번 호출해 약 5ms다.

런타임 시작 비용도 측정해 대안을 가렸다. 빈 스크립트 30회 기준으로 sh는 약 3.3ms, awk는 약 1.6ms, perl은 약 3.4ms, python3은 약 72ms였다. python3은 시작 비용만으로 현재 총합을 넘겨 per-render 도구로는 부적합하다. macOS 기본 awk(BWK awk 20200816)는 `mktime`과 `strftime` 시간 함수를 지원하지 않아, 순수 awk로는 리셋 시간 계산을 할 수 없다. 이 측정에 따라 렌더 경로는 POSIX sh를 유지하기로 결정했다.

## 무손실 제약이 배제한 접근

git 브랜치 조회를 `.git/HEAD` 파일 직접 읽기로 바꾸면 빠르지만 두 경우에서 브랜치 표시가 사라진다. 실제 저장소로 재현해 확인했다.

- 저장소의 하위 디렉터리에서 실행하면 그 위치에는 `.git`이 없어 브랜치를 찾지 못한다. `git rev-parse`는 상위로 올라가며 저장소를 찾으므로 정상 동작한다.
- git worktree에서는 `.git`이 디렉터리가 아니라 `gitdir:` 포인터를 담은 파일이라, `.git/HEAD`를 파일로 읽으면 실패한다. worktree는 이 사용자가 상시 쓰는 환경이다.

손실 없이 직접 읽기를 하려면 git의 저장소 탐색(상위 탐색, `.git` 파일의 `gitdir` 포인터 추적, worktree HEAD 위치, detached 판정)을 재구현해야 하고, 그래도 놓친 git 내부 규칙이 남을 잔여 위험이 있다. 무손실 제약과 충돌하므로 직접 읽기 대체는 채택하지 않는다. 대신 git을 진실의 원천으로 유지하고 결과를 캐싱한다.

## 최적화 항목

각 항목은 프로토타입으로 실효성을 측정해 확인했다. 측정은 렌더 50회 반복 기준이며 회당 값으로 환산해 적는다.

### 축약 로직을 같은 프로세스로 흡수

매 렌더 `sh shorten.sh`를 두 번 띄우는 대신, 축약 함수를 `statusline.sh`와 같은 프로세스에서 호출한다.

`shorten.sh`는 zsh 프롬프트도 `--plain` 모드로 쓰는 공유 유틸이므로 삭제하지 않는다. `strip_control`, `shorten_path`, `shorten_branch` 세 함수를 소스 가능한 공유 파일 `scripts/shorten-lib.sh`로 옮긴다. `shorten.sh`는 이 lib을 `.`으로 불러온 뒤 색 모드를 파싱하고 하위 명령을 분기하는 얇은 CLI 래퍼로 남는다. 프롬프트가 호출하는 CLI 계약은 그대로다. `statusline.sh`는 시작 시 이 lib을 한 번 소스해 함수를 직접 호출하므로 축약 때문에 뜨던 sh 서브프로세스가 사라진다.

측정 결과, 경로와 브랜치 축약을 서브프로세스 두 번으로 하면 회당 약 31.9ms, 같은 함수를 in-process로 호출하면 약 19.8ms였다. 서브프로세스 시작 제거만으로 약 12ms가 줄었다.

lib으로 옮기면서 함수 내부의 프로세스 호출도 없앤다. `shorten_path`가 상위 경로를 훑는 루프는 `dirname`을 경로 깊이만큼 호출한다. 깊이 9인 경로에서 이 루프만 회당 약 12.3ms였고, 같은 탐색을 파라미터 확장으로 바꾸면 회당 약 0.1ms로 떨어졌다. 다만 `${var%/*}`는 슬래시가 없는 문자열을 줄이지 못해 그대로 두면 무한 루프가 된다. 슬래시 유무를 `case`로 가른 뒤 슬래시가 없으면 루프를 끝내는 가드를 함께 둔다. `shorten_branch`의 티켓 추출에 쓰는 `expr`도 `case` 패턴과 파라미터 확장으로 바꾼다. 이 교체는 프롬프트 경로의 fork도 함께 줄인다.

### 캐싱 계층

git과 큰 파일 파싱 결과를 캐싱하되, 값은 언제나 권위 있는 출처가 결정하게 해서 손실을 막는다. 캐시는 기존 캐시 디렉터리 `${XDG_CACHE_HOME:-$HOME/.cache}/claude-statusline/` 아래에 둔다.

git 브랜치는 캐시가 없거나 무효일 때만 조회한다. 캐시 미스에서 `git rev-parse --git-path HEAD --abbrev-ref HEAD`를 한 번 호출해 브랜치 이름과 HEAD 파일 경로를 함께 얻는다. 이때 반환되는 HEAD 경로는 현재 디렉터리 기준 상대경로일 수 있으므로(서브디렉토리에서 `../../.git/HEAD` 형태로 나옴을 확인했다) 절대경로로 정규화해 저장한다. HEAD 파일의 절대경로, 그 파일의 첫 줄 내용, 브랜치 이름을 현재 디렉터리별로 저장한다.

무효화 신호로는 HEAD 파일의 수정 시각이 아니라 첫 줄 내용을 쓴다. 다음 렌더의 빠른 경로는 저장된 HEAD 파일의 첫 줄을 셸 내장 `read`로 읽어(프로세스 없음) 저장된 값과 비교하는 것이다. 같으면 저장된 브랜치를 재사용하고 git을 부르지 않으며, 다르거나 파일이 없으면 다시 조회한다. 수정 시각 기반 비교는 셸 `test`의 `-nt` 연산자가 1초 단위라 같은 초에 일어난 브랜치 전환을 놓치지만, 내용 비교는 이 문제가 없다. 실제로 같은 초에 브랜치를 바꿔도 첫 줄 내용 비교가 변경을 잡는 것을 확인했다. 브랜치 값을 git이 판정하므로 하위 디렉터리, worktree, detached 상태가 모두 지금과 동일하게 나온다. 측정 결과, `git rev-parse` 조회는 회당 약 6.3ms, 내장 `read`로 내용을 비교하는 캐시 적중은 회당 약 0.12ms였다.

Claude 계정 이메일은 `~/.claude.json`을 캐시 키 대상으로 삼되, 이 파일이 계정 정보가 파일 끝(약 7300줄 중 7222번째 줄)에 있어 매 렌더 awk 스캔이 회당 약 9ms 든다. 또 이 파일은 런타임 상태 파일이라 이메일이 바뀌지 않아도 약 45초 간격으로 다시 쓰인다. 그래서 셸 `test`의 `-nt`로 캐시 파일 대비 `~/.claude.json`이 더 새 것인지만 확인한다. 이 비교는 프로세스를 만들지 않아 캐시 적중이 회당 약 0.12ms다. 파일이 다시 쓰이면 다음 렌더에서 한 번 awk로 재스캔해 이메일을 갱신하므로, 로그인으로 계정이 바뀌어도 다음 렌더에 반영된다.

AWS 세션 만료 시각은 saml2aws가 설치돼 있을 때만, credentials 파일 대비 `-nt` 비교로 파싱 결과를 재사용한다.

비용은 이미 백그라운드에서 캐시 파일로 기록되므로 그대로 둔다.

### date 호출 한 번으로 통합

현재 여러 함수가 각자 `date`로 현재 epoch를 얻어 렌더당 약 10회 호출한다. 스크립트 앞에서 현재 epoch와 시계 표시 문자열을 한 번의 호출로 받아, 리셋 시간 계산과 rate 페이스 계산, AWS 잔여 시간 계산이 그 값을 공유한다.

### 모델 문자열 파싱에서 sed 제거

`format_model`이 모델 표시 문자열에서 이름과 버전을 뽑을 때 쓰는 sed 파이프라인은 조건에 따라 sed를 최대 네 번 호출해 회당 약 5ms다. 이를 `case` 패턴과 파라미터 확장으로 바꿔 sed 호출을 없앤다. 결과 문자열은 지금과 같다.

## 테스트 전략

기존 테스트 스위트는 레이아웃, 막대, 색, 표시기를 fixture로 검증한다. 이 스위트가 계속 통과하는 것이 무손실의 일차 근거다. Red-Green 절차를 따라, 동작을 바꾸기 전에 실패하는 테스트를 먼저 추가한다.

추가할 회귀 테스트는 다음을 확인한다.

- 캐시가 없을 때는 git을 실행해 브랜치를 채운다.
- 유효한 캐시가 있을 때는 git을 실행하지 않고 캐시 값을 쓴다.
- HEAD 파일 첫 줄 내용이 바뀌면 캐시가 무효화되고 새 브랜치가 나온다.
- 저장소 하위 디렉터리와 git worktree에서 브랜치가 정확히 나온다. 이것이 무손실 가드다.
- `~/.claude.json`이 그대로면 이메일을 다시 스캔하지 않고, 다시 쓰이면 반영한다.
- 경로 축약의 상위 탐색 루프가 슬래시 없는 세그먼트에서 무한 루프에 빠지지 않는다. `dirname`을 파라미터 확장으로 바꾸면서 생길 수 있는 회귀라 명시적으로 확인한다.

git 실행 여부는 테스트가 관찰할 수 있어야 하므로, 테스트에서 가짜 git을 PATH 앞에 두어 호출 여부와 인자를 기록하는 방식으로 확인한다.

최적화 전후의 벤치마크 수치를 같은 fixture와 반복 횟수로 측정해 기록한다. 기준점은 git 저장소를 현재 디렉터리로 둔 렌더 30회에 총 4.690초, 회당 약 156ms다. 각 최적화 항목의 개별 실효는 프로토타입에서 이미 측정했고, 구현 후 전체 경로에서 다시 측정해 합산 효과를 확인한다.

## 위험과 완화

캐시가 오래된 값을 보여줄 위험은, 시간 기반 만료가 아니라 원본 파일의 수정 시각으로 무효화하고 git을 진실의 원천으로 유지해 완화한다. 브랜치가 바뀌면 HEAD 파일 수정 시각이 달라져 즉시 다시 조회한다.

`shorten.sh` 리팩터가 zsh 프롬프트를 깨뜨릴 위험은, CLI 래퍼의 인자 계약을 그대로 두고 축약 함수의 기존 테스트로 가드해 완화한다.

## 외부 의존

- POSIX sh, `git`, `date`, `awk`가 실행 환경에 있어야 한다. 현재 스크립트와 같은 가정이다.
- 캐시 디렉터리는 `${XDG_CACHE_HOME:-$HOME/.cache}/claude-statusline/`를 쓴다.
