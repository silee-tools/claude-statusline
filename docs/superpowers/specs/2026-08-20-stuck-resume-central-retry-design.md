# stuck-resume 전역 재시도 조정 설계

## 한 줄 정의

`stuck-resume`은 같은 로컬 머신에서 `StopFailure`가 발생한 세션을 하나의 전역 상태로 조정해 실패 확인용 호출을 직렬화하고, 한 세션의 정상 완료가 확인되면 대기 중인 모든 세션을 즉시 재개한다. 이 상태는 중복 호출과 대화 기록 오염과 자원 사용을 줄이면서 재시도를 맡은 프로세스가 종료돼도 다른 세션이 이어받게 한다.

## 목표

- 같은 머신의 모든 Claude Code 세션과 지원 오류 원인을 하나의 재시도 범위로 묶는다.
- 실패가 지속되는 동안 실제 재개 호출 사이에 전역 지수 백오프를 적용한다.
- 새로 실패한 세션에는 등록 시각을 기준으로 한 최초 탐침 기회를 한 번 제공한다.
- 한 세션의 정상 완료가 확인되면 대기 중인 모든 세션의 훅을 조기 종료해 즉시 재개한다.
- 재시도를 맡은 세션이나 훅 프로세스가 종료돼도 다른 대기 세션이 정해진 시각에 재시도를 이어 간다.
- 대기 중에는 네트워크 요청과 상태 폴링을 하지 않고 로컬 프로세스와 파일 접근을 최소화한다.
- 셸 구현과 테스트는 POSIX `sh`를 유지한다.

## 비목표

- Claude Code의 `autoContinueAtUsageLimit` 설정을 검사하거나 변경하지 않는다.
- Claude Code 자체 자동 재개와 플러그인 재개가 겹치는 상황을 차단하지 않는다.
- 계정이나 프로젝트별로 재시도 범위를 나누지 않는다.
- SQLite와 상주 데몬과 외부 서비스를 도입하지 않는다.
- 무작위 지터를 추가하지 않는다.
- 정상 작업의 진행 상태를 추적하거나 작업 중과 프로세스 종료를 구분하지 않는다.
- `StopFailure`가 발생하지 않은 세션을 중앙 상태에 등록하지 않는다.

## 훅 구성

`StopFailure` 훅은 `rate_limit`, `authentication_failed`, `server_error`, `overloaded`를 받는다.
`StopFailure`와 `Stop`은 같은 `resume.sh`를 호출하며 스크립트가 `hook_event_name`으로 처리 경로를 나눈다.

각 `StopFailure` 훅 프로세스는 자기 세션을 전역 상태에 등록하고 재개 권한을 얻을 때까지 기다린다.
재개 권한을 얻은 훅은 원인에 맞는 재개 문장을 표준 오류에 쓰고 종료코드 2로 끝난다.
`asyncRewake`는 종료코드 2를 받은 Claude Code 세션을 깨운다.

`Stop` 훅은 현재 재시도 대상으로 기록된 세션이 정상적으로 턴을 마쳤는지 확인한다.
활성 재시도 세대가 없거나 `Stop`의 세션 식별자가 현재 대상과 다르면 상태를 바꾸지 않고 즉시 끝난다.
현재 대상과 일치하면 성공 세대를 기록하고 대기 중인 모든 `StopFailure` 훅에 재개 신호를 보낸다.

## 전역 상태

상태 루트는 `${CLAUDE_RESUME_STATE_DIR:-${XDG_STATE_HOME:-$HOME/.local/state}/stuck-resume}`다.
새 중앙 상태는 상태 루트 아래의 버전 전용 디렉터리에 둬 이전 플러그인 세션이 쓰는 원인별 카운터와 충돌하지 않게 한다.

중앙 상태는 다음 정보만 가진다.

- 현재 에피소드와 단조 증가하는 재시도 세대 번호를 가진다.
- 마지막 실제 재개 시각과 다음 백오프 단계를 가진다.
- 현재 재시도 대상의 세션 식별자와 세대 번호와 인계 시각을 가진다.
- 오류 원인별 최초 발생 시각과 종료 시각을 가진다.
- 대기 세션별 훅 프로세스 식별자와 등록 세대와 최초 탐침 사용 여부를 가진다.
- 정상 완료가 확인된 마지막 세대 번호를 가진다.

세션 식별자는 파일 이름에 쓰기 전에 영문자와 숫자와 밑줄과 하이픈만 허용한다.
값이 없거나 허용하지 않은 문자가 있으면 `unknown`으로 격리한다.
프로세스 식별자는 숫자만 허용하며 현재 등록과 일치하는 훅 프로세스만 신호 대상으로 삼는다.

## 동시성 제어

상태 변경은 `mkdir`의 원자성을 이용한 전역 잠금 안에서 수행한다.
잠금 구간에서는 상태 읽기와 다음 세대 결정과 파일 교체만 수행하며 대기와 신호 전송은 잠금 밖에서 수행한다.

잠금 소유자는 프로세스 식별자와 획득 시각을 남긴다.
소유 프로세스가 없거나 잠금 획득 뒤 30초가 지나면 다른 훅이 잠금을 회수한다.
만료 판정과 재시도 시각 계산은 모두 같은 머신의 시스템 epoch 초를 사용한다.

상태 파일은 같은 디렉터리에서 임시 파일을 완성한 뒤 원자적으로 이름을 바꿔 교체한다.
읽는 쪽은 완성되지 않은 중간 레코드를 관찰하지 않는다.

## 등록과 최초 탐침

세션에서 첫 `StopFailure`가 발생하면 훅은 세션과 오류 원인을 등록한다.
새 세션의 최초 탐침 시각은 등록 시각에서 시작 지연 뒤이며 기본값에서는 30초 뒤다.

새 세션 등록은 전역 백오프 단계를 초기화하지 않는다.
최초 탐침도 마지막 실제 재개 호출에서 시작 지연이 지나야 실행할 수 있으므로 여러 세션이 동시에 모델을 호출하지 않는다.

세션 A가 시각 T에 등록되고 세션 B와 C가 각각 T+N과 T+N+M에 등록되면 각 세션은 자기 등록 시각에서 시작 지연 뒤 최초 탐침 자격을 얻는다.
실제 탐침은 자격을 얻은 세션 가운데 가장 이른 등록을 우선하며, 직전 호출과 시작 지연 이상 떨어진 시각에 실행한다.
등록 시각이 같으면 세션 식별자의 바이트 순서로 대상을 정해 선택 결과를 재현할 수 있게 한다.

최초 탐침은 세션마다 에피소드 안에서 한 번만 사용한다.
같은 세션의 재개가 다시 `StopFailure`로 끝나면 이후 시각은 전역 지수 백오프로 계산한다.

## 지수 백오프

에피소드의 첫 재개 지연은 `CLAUDE_RESUME_WAIT_SECONDS`이며 기본값은 30초다.
값은 1초 이상 480초 이하의 정수만 허용하며 범위를 벗어나거나 잘못된 값은 기본값 30초로 바꾼다.
에피소드를 처음 등록한 훅이 시작 지연을 전역 상태에 고정하며 뒤에 등록된 세션의 환경변수 값은 진행 중인 에피소드를 바꾸지 않는다.
재개 실패가 확인될 때마다 다음 전역 지연을 직전 값의 2배로 늘리되 480초를 넘기지 않는다.
480초에 도달한 뒤에는 종료 시각까지 그 값을 유지한다.
기본값을 쓰면 지연은 30초, 60초, 120초, 240초, 480초가 된다.
절대 상한은 각 비동기 `StopFailure` 훅이 600초 제한 시간 안에서 상태를 다시 확인하고 소유권을 넘길 수 있게 한다.

현재 재시도 세션에서 `StopFailure`가 다시 발생하면 해당 시도가 실패한 것으로 확정한다.
훅은 활성 시도를 닫고 백오프 단계를 한 칸 올린 뒤 새 대기 등록을 만든다.

새 세션의 최초 탐침은 긴 백오프 중에도 한 번 허용하지만 실제 호출의 전역 최소 간격인 시작 지연은 지킨다.
세션이 많이 등록돼도 각 신규 세션이 백오프를 우회할 수 있는 횟수는 한 번으로 제한된다.

`CLAUDE_RESUME_MAX_ATTEMPTS`는 전역 에피소드에서 복구 확인 전에 실행할 직렬 탐침 호출 수의 상한이다.
기본값은 `0`이며 횟수로 제한하지 않고 오류별 종료 시각만 적용한다.
값은 0 이상의 정수만 허용하며 잘못된 값은 기본값 `0`으로 바꾼다.
양수를 명시하면 전역 종료 시각에 도달하기 전이라도 해당 횟수의 호출을 실행한 뒤 새 직렬 탐침을 시작하지 않는다.
호출 상한도 에피소드를 처음 등록한 훅의 값을 전역 상태에 고정한다.
`Stop`으로 복구가 확인된 뒤 모든 대기 훅을 조기 종료하는 호출은 이 상한에 포함하지 않는다.

## 정상 완료와 전체 조기 재개

현재 활성 레코드가 가리키는 세션에서 `Stop`이 발생하면 해당 세대가 정상 완료된 것으로 확정한다.
`Stop` 훅은 잠금 안에서 성공 세대를 기록하고 활성 시도를 소비해 같은 `Stop`이 성공 전파를 반복하지 못하게 한다.

잠금이 풀리면 `Stop` 훅은 등록된 모든 대기 훅에 한 번의 로컬 신호 전송으로 재개 신호를 보낸다.
신호를 받은 각 훅은 자기 대기를 취소하고 등록을 정리한 뒤 원인에 맞는 재개 문장을 쓰고 종료코드 2로 끝난다.

성공 전파에서는 전역 최소 간격을 적용하지 않는다.
복구가 확인된 시점에 모든 세션을 즉시 재개하는 동작이 세션별 예약을 계속 직렬화하는 것보다 우선한다.

각 대기 훅은 신호 처리기를 설치한 뒤 중앙 상태에 등록한다.
등록과 신호가 겹쳐 직접 신호를 받지 못한 훅은 자기 등록 세대보다 같거나 새로운 성공 세대를 확인하고 즉시 종료코드 2로 끝난다.

죽은 훅 프로세스에 대한 신호 실패는 무시하고 나머지 훅에 계속 전송한다.
신호 대상 목록은 현재 등록 레코드에서 만들며 오래된 프로세스 식별자를 다른 프로세스에 보내지 않도록 현재 훅 프로세스인지 확인한다.

## 결과가 없는 시도의 인계

재개한 세션에서 다음 재시도 시각까지 `StopFailure`와 `Stop`이 모두 발생하지 않아도 성공 여부를 추정하지 않는다.
세션이 작업 중인지 종료됐는지 구분하지 않고 현재 활성 세대를 만료시킨 뒤 자격이 있는 다음 대기 세션에 탐침 기회를 준다.

인계 시각은 별도 제한시간을 추가하지 않고 현재 지수 백오프로 계산한 다음 재시도 시각을 그대로 사용한다.
따라서 감시 세션이나 훅 프로세스가 종료돼도 다른 대기 세션은 480초보다 오래 소유권을 기다리지 않는다.

활성 대상이 다른 세션으로 넘어간 뒤 늦게 도착한 `Stop`은 세션 식별자가 현재 활성 레코드와 일치하지 않으므로 성공 전파를 일으키지 않는다.
한 세션은 재개 결과로 새 `StopFailure`를 등록하기 전에는 다시 활성 대상으로 선택되지 않으므로, 같은 세션의 과거 `Stop`을 새 세대의 성공으로 오인하지 않는다.
늦게 도착한 `StopFailure`는 새로운 실패 등록으로 처리하되 이미 소비한 최초 탐침을 복원하거나 같은 오류의 종료 시각을 연장하지 않는다.

## 오류별 종료 시각

`server_error`, `overloaded`, `authentication_failed`의 종료 시각은 해당 오류가 전역 에피소드에서 처음 발생한 시각부터 3시간 뒤다.
같은 오류가 반복돼도 최초 발생 시각과 종료 시각은 바꾸지 않는다.

`rate_limit`은 훅이 가리키는 세션 기록의 최신 API 오류 레코드에서 숫자형 `quotaLimits.resetsAt`을 먼저 읽는다.
구조화된 값이 없으면 `last_assistant_message`에 표시된 `resets` 시각을 해석한다.
리셋 예정 시각을 얻으면 종료 시각은 리셋 예정 시각에서 1시간 뒤다.
두 경로에서 모두 리셋 예정 시각을 얻지 못하면 최초 `rate_limit` 발생부터 3시간 뒤를 종료 시각으로 사용한다.

여러 오류가 한 에피소드에 등록되면 원인별 종료 시각 가운데 가장 늦은 시각을 전역 종료 시각으로 사용한다.
새 오류가 처음 발생하면 전역 종료 시각이 늦어질 수 있지만 이미 발생한 오류의 반복은 늘리지 않는다.

현재 시각이 전역 종료 시각에 도달하면 대기 훅은 종료코드 0으로 끝나며 더 이상 세션을 깨우지 않는다.
활성 시도가 없고 정상 완료가 확인된 마지막 세대보다 새로운 대기 등록도 없으면 현재 에피소드를 닫는다.
성공 전파를 기다리는 이전 세대의 등록 파일은 새 에피소드 시작을 막지 않으며, 이후의 `StopFailure`는 세대 번호를 계속 증가시켜 새 에피소드를 시작한다.

## 실패와 경합 처리

- 잠금 소유 훅이 종료되면 다른 훅이 30초 뒤 잠금을 회수한다.
- 현재 재시도 대상이 종료되면 다음 인계 시각에 다른 대기 훅이 활성 세대를 만료시키고 이어받는다.
- 대기 훅이 종료되면 다른 훅이 등록 레코드의 프로세스 생존 여부를 확인해 오래된 항목을 제거한다.
- 성공 신호 전송 중 일부 프로세스가 사라져도 살아 있는 훅의 조기 재개는 계속한다.
- 상태 파일이 없거나 일부 값이 손상되면 손상된 레코드만 버리고 안전한 기본값으로 새 에피소드나 등록을 만든다.
- 시스템 시각이 뒤로 이동해 계산 결과가 음수가 되면 시작 지연을 적용하고 종료 시각을 새로 늘리지 않는다.

## 프로세스와 호출 횟수

상주 중앙 제어기 대신 이미 실행 중인 `StopFailure` 훅 프로세스가 짧은 잠금 아래에서 같은 상태를 갱신한다.
각 대기 훅은 등록할 때 중앙 상태를 확인하고, 자기 예약 시각이 됐거나 성공 신호를 받았을 때 다시 확인한다.
다른 훅이 먼저 재개 권한을 얻으면 다음 예약 시각까지 다시 잠들며 고정 간격으로 상태를 조회하지 않는다.
대기 중에는 네트워크 요청과 반복 파일 조회를 하지 않는다.

`Stop` 훅은 모든 정상 종료에서 실행되지만 활성 재시도 세대가 없으면 셸 내장 파일 검사 뒤 즉시 끝난다.
활성 세대와 세션이 일치할 때만 상태 갱신과 대기 훅 신호 전송을 수행한다.

성공 전파에는 대기 훅 수에 비례한 로컬 신호 대상이 필요하다.
여러 프로세스 식별자를 한 번의 셸 내장 `kill` 호출에 전달해 별도 프로세스 생성과 훅별 명령 실행을 늘리지 않는다.
세션별 등록 시각의 차이가 탐침 시각을 자연스럽게 분산하므로 무작위 수 생성과 별도 지터 상태는 두지 않는다.

## 상태 전환

새 상태 형식은 기존 원인별 카운터 파일과 다른 버전 전용 디렉터리에 추가한다.
이전 플러그인을 이미 로드한 세션은 기존 카운터를 계속 사용하고 새 플러그인을 로드한 세션만 중앙 상태에 참여한다.

| 단계 | 성립해야 하는 상태 | 시작 조건 |
|---|---|---|
| Expand | 새 중앙 상태와 기존 카운터가 서로 다른 경로에서 함께 동작한다. | 새 플러그인 버전을 배포할 때 시작한다. |
| Migrate | 실행 중인 모든 Claude Code 세션이 새 플러그인 버전을 로드해 중앙 상태만 갱신한다. | 새 버전 설치와 기존 세션 재시작이 완료됐음을 확인한 뒤 판정한다. |
| Contract | 기존 원인별 카운터 파일과 호환 처리를 제거한다. | 모든 세션의 전환과 새 중앙 상태의 운영 검증을 확인한 뒤 별도 변경으로 수행한다. |

첫 배포 단계는 Expand까지만 수행한다.
Migrate는 새 버전 설치 뒤 세션을 재시작하는 운영 단계이며, Contract는 배포 이력과 전환 완료를 확인한 뒤 시작하는 별도 작업이다.

## 테스트 전략

동작 변경은 기존 `stuck-resume/tests/resume.test.sh`에 실패하는 계약을 먼저 추가한 뒤 구현을 통과시킨다.
현재 시각과 상태 루트와 신호 전송은 테스트에서 결정적인 값으로 바꿀 수 있게 하되 제품에서 바뀌지 않는 정책을 일반 설정으로 만들지 않는다.

다음 동작을 실제 훅 프로세스와 격리된 임시 상태 디렉터리로 검증한다.

- 세 세션의 등록 시각이 다르면 각각 시작 지연 뒤 최초 탐침 자격을 얻고 실제 재개는 시작 지연 이상의 간격을 지킨다.
- 실패가 반복되면 전역 지연이 시작값에서 480초까지 늘고 절대 상한을 넘지 않는다.
- 신규 세션은 최초 탐침을 한 번 얻지만 전역 백오프 단계를 초기화하지 않는다.
- 현재 재시도 세션의 `StopFailure`만 현재 시도를 실패로 확정한다.
- 현재 재시도 세션의 `Stop`은 모든 대기 훅을 종료코드 2로 조기 종료한다.
- 다른 세션의 `Stop`과 만료된 세대의 늦은 `Stop`은 성공 전파를 일으키지 않는다.
- 직접 신호를 놓친 훅도 성공 세대를 읽고 조기 종료한다.
- 현재 재시도 훅이나 잠금 소유 훅을 강제 종료해도 다른 세션이 인계한다.
- 원인별 3시간 종료 시각과 `rate_limit`의 리셋 예정 시각에서 1시간 뒤 종료 시각을 검증한다.
- 리셋 예정 시각이 없으면 `rate_limit`이 최초 실패부터 3시간을 사용한다.
- 여러 오류가 있으면 가장 늦은 종료 시각을 사용하고 같은 오류 반복은 시각을 연장하지 않는다.
- 입력과 상태 파일의 잘못된 세션 식별자와 숫자 필드는 상태 루트 밖의 파일이나 다른 프로세스 신호로 이어지지 않는다.
- Claude Code 자체 자동 재개 설정의 유무가 훅 실행을 차단하거나 설정 파일 변경을 일으키지 않는다.
- `CLAUDE_RESUME_WAIT_SECONDS`가 시작 지연과 전역 최소 간격을 함께 조정하고 `CLAUDE_RESUME_MAX_ATTEMPTS`의 양수 값이 전역 호출 수를 제한한다.

집중 테스트가 통과한 뒤 저장소 표준 전체 검증 명령을 실행해 두 플러그인의 셸 스위트와 Go 테스트 종료코드를 모두 확인한다.
행동 변경 보고에는 실패를 먼저 확인한 검사 수와 최종 통과 및 실패 수를 함께 기록한다.
