# 74칼럼 3행 압축 레이아웃 설계

## 한 줄 정의

statusline 이 차지하는 화면 높이를 최대 세 행으로 제한하고 첫 행을 74칼럼 안에 담아, 좁고
낮은 터미널에서도 대화 영역을 최대한 남긴다.

## 목표

- 어떤 입력에서도 렌더 결과가 세 행을 넘지 않는다. 첫 행은 경로와 브랜치를 잘라 74칼럼
  안에 들어오게 한다. 둘째 행과 셋째 행은 자르지 않는다. 셋째 행은 내용이 코드로 정해져
  있어 그 안에 들고, 둘째 행은 계정 이메일과 gh 라벨 같은 환경값의 길이에 따라 달라진다.
- 가변 길이 항목인 경로와 브랜치가 예산을 넘으면 잘라 내되, 잘린 사실을 화면에서 알 수 있다.
- 소진율, 리셋까지 남은 시간, 페이스 초과 여부를 막대 없이도 읽을 수 있다.
- 계정, 인증, 모델, 추론 강도, 버전, 세션 식별자를 모두 남긴다.
- 렌더 경로는 POSIX sh 를 유지한다.

## 비목표

- 터미널 폭을 실행 중에 감지하지 않는다. 상한은 74칼럼 상수다.
- 비용을 표시하지 않는다. 24시간, 7일, 당월 금액과 모델별 분해를 모두 뺀다.
- 비용 집계 파이프라인을 제거하지 않는다. 캐시를 갱신하는 배경 작업은 그대로 둔다.
- GitHub 계정 세그먼트의 내용을 이 설계에서 정의하지 않는다. 그 계약은 별도 설계가 정하며,
  이 설계는 그 세그먼트가 돌려주는 문자열을 배치만 한다.

## 폭 상한을 상수로 두는 이유

Claude Code 는 statusline 에 터미널 폭을 넘기지 않는다. 폭을 알아내려면 부모 프로세스의 tty
이름을 얻어 그 장치의 창 크기를 읽어야 하고, 그 조회에 렌더마다 프로세스가 두 개 더 든다.
상한을 상수로 두면 그 비용이 사라지는 대신 74칼럼보다 좁은 터미널에서는 행이 접힌다. 접힘은
행 수를 늘리므로, 이 도구를 쓰는 터미널이 74칼럼 이상이라는 전제가 깨지면 상한값을 다시 정한다.

## 행 구성

세 행은 성격이 다른 정보를 나눠 담는다. 위치가 맨 위에 오고, 자주 바뀌지 않는 계정과 상수값이
가운데에 오며, 가장 자주 확인하는 게이지가 프롬프트에 가장 가까운 맨 아래에 온다.

| 행 | 담는 것 |
|---|---|
| 1 | 시각, 경로, 브랜치 |
| 2 | Claude 계정, GitHub 계정, AWS 세션, Claude Code 버전, 세션 식별자 |
| 3 | 컨텍스트 소진율, 모델, 추론 강도, 5시간 한도, 7일 한도 |

세그먼트 사이는 공백 한 칸으로 나눈다. 값이 없는 세그먼트는 자연히 빠지고 남은 세그먼트만
이어 붙는다. 세 행 중 어느 행이든 담을 값이 하나도 없으면 그 행을 생략한다.

다음은 평상시 렌더다.

```text
09:24 ~/↪2/claude-statusline main
dev@example.com gh@personal aws:✓ v2.0.31 ⧉ 3f9c1a
ctx 32% Opus 5 ● 5h 37% ↺2h0m 7d 68%▲ ↺3d16h
```

다음은 각 항목이 가장 길어지는 렌더다. 경로와 브랜치가 예산을 넘어 잘렸고, 인증이 만료됐으며,
두 한도가 모두 소진되고 페이스도 초과한 상태다.

```text
09:24 ~/↪1/webapp/↪2/PROJ-1469-connect… feature/PROJ-1469-connect-api-se…
dev@example.com gh@personal aws:expired v2.0.31 ⧉ 3f9c1a
ctx 100% Sonnet 4.5 ● 5h 100%▲ ↺4h59m 7d 100%▲ ↺6d23h
```

## 행1 폭 예산과 절단

시각이 5칼럼, 세그먼트 사이 공백이 두 칸, 브랜치 아이콘이 한 칸을 쓴다. 남는 66칼럼을 경로와
브랜치가 나눈다.

```text
74 = 5(시각) + 1(공백) + 경로 + 1(공백) + 1(브랜치 아이콘) + 브랜치
```

배분은 다음 규칙을 따른다. 두 값의 폭을 더해 66 이내면 둘 다 그대로 낸다. 넘으면 각자 33칼럼을
상한으로 두되, 한쪽이 33칼럼을 다 쓰지 않으면 남는 몫을 다른 쪽에 넘긴다. 이 규칙은 짧은
브랜치와 깊은 경로가 함께 오는 흔한 조합에서 경로를 최대한 살린다.

| 조건 | 경로에 주는 폭 | 브랜치에 주는 폭 |
|---|---|---|
| 경로 + 브랜치 ≤ 66 | 그대로 | 그대로 |
| 초과하고 브랜치 ≤ 33 | 66 − 브랜치 | 그대로 |
| 초과하고 경로 ≤ 33 | 그대로 | 66 − 경로 |
| 초과하고 둘 다 33 초과 | 33 | 33 |

브랜치가 없으면 아이콘과 앞 공백도 함께 빠지므로 경로가 68칼럼까지 쓴다.

절단은 문자열 뒤쪽을 잘라 내고 그 자리에 줄임표 `…` 한 칸을 붙인다. 줄임표는 마침표 세 개
대신 한 칸짜리 문자를 써서 두 칸을 아낀다. 앞쪽을 남기는 이유는 경로와 브랜치 모두 앞부분이
대상을 특정하기 때문이다.

경로와 브랜치는 절단 전에 지금의 축약을 먼저 거친다. 경로는 중간 구간을 `↪N` 으로 접고,
브랜치는 접두와 티켓 번호를 남긴 채 가운데 낱말을 접는다. 절단은 그 결과가 배분받은 폭을
넘을 때만 일어난다.

## 표시 폭 계산

절단은 글자 수가 아니라 표시 폭을 기준으로 한다. 한글처럼 한 글자가 두 칸을 차지하는 문자가
브랜치와 경로에 실제로 들어오므로, 글자 수로 자르면 행이 예산을 넘는다. 두 칸짜리 문자를 반으로
쪼개지 않으며, 남은 자리가 한 칸뿐이면 그 문자를 넣지 않고 줄임표를 붙인다.

## 게이지 표기

막대를 없애고 소진율 숫자만 남긴다. 라벨은 지금의 `ctx`, `5h`, `7d` 를 그대로 쓴다.

페이스 초과는 막대 안의 `▓` 대신 소진율 바로 뒤에 붙는 `▲` 로 나타낸다. 판정 기준은 지금과
같다. 경과 시간에 비례한 예산보다 소진이 앞서 있으면 기호를 붙이고, 앞선 폭이 20분의 3, 곧
15퍼센트포인트 이상이면 빨강, 그보다 적으면 노랑으로 칠한다. 앞서지 않았으면 기호를 붙이지
않는다.

절대 소진율에 따른 색 승격은 지금 규칙을 유지한다. 컨텍스트는 40퍼센트에서 노랑, 70퍼센트에서
빨강으로 올라가고, 두 한도는 80퍼센트에서 노랑, 90퍼센트에서 빨강으로 올라간다. 소진율 색과
페이스 초과 색은 서로 다른 신호다. 앞의 것은 한도에 얼마나 가까운지를, 뒤의 것은 시간 대비
얼마나 빨리 쓰는지를 나타내므로 한 색으로 합치지 않는다.

리셋까지 남은 시간은 지금 형식을 그대로 쓴다.

## 세션 식별자

전체 UUID 36자 대신 앞 6자를 쓴다. 표시는 마커와 공백을 포함해 `⧉ 3f9c1a` 여덟 칸이다.

앞 6자를 고른 근거는 두 가지다. 첫째, 이 식별자에는 시간 정보가 없다. Claude Code 가 만드는
세션 식별자는 UUID 버전 4라 122비트가 난수이고, 생성 순서와 사전순 사이에 상관이 없다. 그래서
어느 자리를 잘라 내도 최신 세션을 알려 주는 부분은 남지 않는다. 둘째, 유일 식별에는 6자면
넉넉하다. 세션 807개를 대상으로 접두 충돌을 센 결과는 다음과 같다.

| 접두 길이 | 실측 충돌 | 생일 문제 기대 충돌 |
|---|---|---|
| 3자 | 87건 | 79.50건 |
| 4자 | 6건 | 4.97건 |
| 5자 | 0건 | 0.31건 |
| 6자 | 0건 | 0.02건 |

6자에서 기대 충돌이 0.02건이므로 세션 수가 지금의 다섯 배로 늘어도 여유가 있다.

## 빼는 것

| 항목 | 처분 |
|---|---|
| 컨텍스트, 5시간, 7일 막대 20칸 | 제거 |
| 24시간 비용과 모델별 분해 | 제거 |
| 7일 비용, 당월 비용 | 제거 |
| 비용 라벨 정렬용 우측 정렬 헬퍼 | 쓰는 곳이 사라지면 함께 제거 |

비용 캐시를 만드는 배경 작업과 그 캐시 파일은 그대로 둔다. 표시를 되살릴 때 수집부터 다시
만들지 않아도 되게 하기 위해서다.

## 안전장치

경로는 색이 입혀진 채로 절단에 들어온다. 그래서 절단은 색 코드를 폭 0으로 세고 자를 때도 그대로
옮긴다. 이스케이프 시퀀스를 폭 있는 글자로 세거나 시퀀스 중간에서 끊으면 터미널이 깨진다. 잘린
문자열은 색이 열린 채로 끝날 수 있으므로 줄임표 뒤에 리셋을 붙여 닫는다.

경로와 브랜치는 저장소 바깥에서 정해지는 값이므로 지금처럼 제어 문자를 제거한 뒤 다룬다.

## 테스트 전략

렌더 결과를 픽스처로 검증하는 지금 방식을 따른다. 실패를 먼저 확인한 뒤 통과시킨다.

행 수는 렌더 결과 전체를 대상으로 단언한다. 어떤 픽스처에서도 행이 셋을 넘지 않는지 확인한다.
폭 상한 74는 첫 행에만 단언한다. 둘째 행과 셋째 행은 자르지 않는다는 목표에 따라 두 행에는
같은 상한을 걸지 않는다. 이 단언은 색 코드를 제거하고 두 칸 문자를 두 칸으로 세는 폭 계산으로
판정한다.

절단은 세 갈래를 각각 고정한다. 예산 안에 들어가 자르지 않는 경우, 한쪽만 자르는 경우, 둘 다
33칼럼으로 자르는 경우다. 한글이 든 브랜치를 픽스처에 넣어 두 칸 문자가 반으로 쪼개지지 않고
폭 기준으로 잘리는지 확인한다.

페이스 초과는 기호가 붙는 조건과 붙지 않는 조건을 함께 고정하고, 노랑과 빨강이 갈리는 경계를
확인한다. 리셋 시각은 고정 숫자로 두지 않고 렌더 시점 기준의 상대값으로 만든다. 고정 숫자는
시간이 지나면 항상 만료로 판정돼 검증이 조용히 무력해진다.

세션 식별자는 알려진 UUID 픽스처의 앞 6자가 그대로 나오는지 확인한다.

## 배포

플러그인은 버전 고정 캐시에서 로드되므로 `claude-statusline/.claude-plugin/plugin.json` 과
`.claude-plugin/marketplace.json` 의 버전을 같은 값으로 올린다. README 의 레이아웃 설명도 이
문서의 행 구성과 게이지 표기에 맞춘다.
