# 터미널 폭에 따른 이중 statusline 레이아웃 설계

## 한 줄 정의

statusline은 감지한 터미널 폭이 80열 이하면 최대 3행 압축 레이아웃을 사용하고,
81열 이상이면 최대 7행 전체 레이아웃을 사용한다.

## 목표

- 좁은 터미널에서는 경로와 브랜치를 실제 표시 폭에 맞춰 잘라 대화 영역을 남긴다.
- 넓은 터미널에서는 막대 게이지, 비용, 전체 세션 식별자를 표시한다.
- 두 레이아웃은 같은 입력 해석, 임계값, 페이스 판정을 사용한다.
- 터미널 크기가 바뀌면 다음 렌더에서 새 폭을 반영한다.
- 폭을 알 수 없을 때 정보를 숨기지 않는 전체 레이아웃으로 안전하게 저하한다.
- 모든 실행 경로는 POSIX `sh`를 유지한다.

## 레이아웃 선택

`CLAUDE_STATUSLINE_WIDTH`가 숫자만 포함하면 해당 값을 감지 결과보다 우선한다. 이
주입 경로는 테스트와 명시적 실행 환경에서 결정적인 폭을 제공한다.

주입값이 없으면 부모 프로세스 체인을 따라 터미널 장치 경로를 찾고 `stty size`로
현재 폭을 읽는다. 터미널 장치 경로만 캐시하며 폭은 렌더마다 다시 읽는다. 따라서 같은
터미널에서 창 크기가 바뀌어도 오래된 폭을 재사용하지 않는다. 환경 변수 `COLUMNS`는
크기 변경 뒤에도 오래된 값이 남을 수 있으므로 판정에 사용하지 않는다.

폭이 80 이하이면 압축 레이아웃을 선택한다. 폭이 81 이상이거나 감지에 실패하면 전체
레이아웃을 선택한다. 감지 실패 시 전체 레이아웃을 쓰면 폭을 추정해 정보를 누락하는 대신
기존의 상세 정보를 모두 보존한다.

## 공통 처리와 레이아웃 책임

`statusline.sh`는 표준 입력 JSON을 한 번 읽고 계정, 모델, 사용량, 리셋 시각과 같은 공통
상태를 만든다. 컨텍스트와 사용 한도의 색 임계값, 사용 속도 판정도 이 단계에서 한 번만
계산한다. 선택된 렌더러만 공통 상태를 행으로 조립한다.

`render-compact.sh`는 압축 행을 조립하고 첫 행의 표시 폭을 제한한다.
`render-full.sh`는 상세 행과 막대 게이지를 조립한다. 압축 레이아웃은 비용 캐시를 읽거나
날짜를 계산하지 않는다. 전체 레이아웃은 첫 행을 자르는 AWK 프로그램을 실행하지 않는다.
선택되지 않은 레이아웃의 전용 작업을 건너뛰어 폭 감지 비용 외의 불필요한 렌더 비용을 막는다.

## 80열 이하 압축 레이아웃

압축 레이아웃은 값이 있는 행만 출력하며 최대 세 행이다.

| 행 | 표시 정보 |
|---|---|
| 1 | 시각, 축약한 현재 경로, Git 브랜치 |
| 2 | Claude 계정, GitHub 계정, AWS 세션, Claude Code 버전, 세션 식별자 앞 6자 |
| 3 | 컨텍스트 소진율, 모델, 추론 강도, 5시간 한도, 7일 한도 |

첫 행은 감지 폭을 상한으로 쓴다. 브랜치가 있으면 시각, 공백, 브랜치 아이콘을 제외한
`폭 - 8`을 경로와 브랜치가 나눈다. 브랜치가 없으면 경로가 `폭 - 6`을 쓴다. 계산 결과가
1보다 작으면 예산을 1로 고정한다.

경로와 브랜치는 기존 축약을 먼저 적용한 뒤 남은 예산을 나눈다. 두 값이 예산 안에 들어오면
그대로 표시한다. 예산을 넘으면 절반씩 배정하고, 한쪽이 배정량보다 짧으면 남은 몫을 다른
쪽에 넘긴다. 잘린 값은 한 칸짜리 줄임표 `…`로 끝낸다. ANSI 색 코드는 폭이 0이며,
한글과 CJK 문자는 두 칸으로 센다. 두 칸 문자를 반으로 자르지 않는다.

압축 레이아웃은 막대와 비용을 표시하지 않는다. 사용 속도가 시간 대비 예산을 넘으면 사용률
뒤에 `▲`를 붙인다. 세션 식별자는 전체 UUID 대신 앞 6자를 표시한다.

## 81열 이상 전체 레이아웃

전체 레이아웃은 값이 있는 행만 출력하며 최대 일곱 행이다.

| 행 | 표시 정보 |
|---|---|
| 1 | 시각, 축약한 현재 경로, Git 브랜치 |
| 2 | Claude 계정, GitHub 계정, AWS 세션 |
| 3 | 컨텍스트 20칸 막대, 소진율, 모델, 추론 강도 |
| 4 | 5시간 한도 20칸 막대, 소진율, 리셋까지 남은 시간 |
| 5 | 7일 한도 20칸 막대, 소진율, 리셋까지 남은 시간 |
| 6 | 24시간, 7일, 당월 비용 |
| 7 | Claude Code 버전, 전체 세션 식별자 |

첫 행은 기존 상세 레이아웃의 가독성을 유지하기 위해 자르지 않는다. 경로와 브랜치가 모두
길면 81열에서 85열 사이의 터미널에서 첫 행이 접힐 수 있다. 이 구간에서도 상세 정보를
우선하는 선택이며, 고정 높이가 더 중요하면 터미널 폭을 80 이하로 줄여 압축 레이아웃을 쓴다.

## 공통 게이지 의미

컨텍스트 사용률은 40퍼센트부터 노랑, 70퍼센트부터 빨강이다. 5시간과 7일 사용률은
80퍼센트부터 노랑, 90퍼센트부터 빨강이다.

두 사용 한도는 소진율과 경과 시간에 비례한 예산을 비교한다. 압축 레이아웃은 앞선 사용량을
`▲`로 표시한다. 전체 레이아웃은 20칸 막대에서 시간 예산을 넘어선 채운 칸을 `▓`로 표시한다.
작은 초과는 노랑이며 약 15퍼센트포인트 이상 앞서면 빨강이다. 20칸 막대를 기준으로 판정하므로
경계는 5퍼센트포인트 단위로 양자화된다.

## 안전장치와 저하 동작

터미널 장치 경로는 허용한 장치 디렉터리 아래의 항목만 사용한다. 캐시 파일에는 장치 경로만
저장하며, 폭 조회가 실패하거나 숫자가 아닌 값을 반환하면 캐시를 신뢰해 폭을 추정하지 않는다.

압축 첫 행을 자르는 AWK 프로그램이 없거나 실패하면 빈 statusline을 출력하지 않는다. 이 경우
경로와 브랜치를 자르지 않은 채 압축 레이아웃을 계속 출력한다. 표시 폭 상한은 지키지 못할 수
있지만 상태 정보와 프롬프트 자체는 보존된다.

외부에서 읽은 경로, 브랜치, 계정 값은 제어 문자를 제거한 뒤 배치한다. 잘린 ANSI 문자열은
줄임표 뒤에 색상 리셋을 붙여 다음 세그먼트로 색이 새지 않게 한다.

## 테스트 전략

폭 감지 테스트는 숫자 주입값, 부모 터미널 탐색, 장치 경로 캐시, 렌더 사이 폭 변경,
잘못된 장치와 감지 실패를 각각 검증한다. 가짜 장치 파일은 테스트 전용 장치 디렉터리에 두어
실제 `/dev` 상태와 독립적으로 실행한다.

렌더 테스트는 80열에서 최대 3행과 첫 행 상한을 확인하고, 81열에서 최대 7행, 20칸 막대,
비용, 전체 세션 식별자를 확인한다. 같은 입력의 80열과 81열 결과가 서로 달라야 한다.
폭 감지 실패와 오래된 `COLUMNS` 값이 함께 있어도 전체 레이아웃을 선택해야 한다.

표시 폭 테스트는 호출자가 전달한 가변 예산, ANSI 코드, 한글과 CJK 문자의 폭, 줄임표와
색상 리셋을 독립적으로 검증한다. 기능 변경은 실패하는 검증을 먼저 확인한 뒤 구현을 통과시킨다.

## 배포

플러그인은 버전 고정 캐시에서 로드된다. 기능을 배포할 때
`claude-statusline/.claude-plugin/plugin.json`과 `.claude-plugin/marketplace.json`의
버전을 같은 SemVer 값으로 올린다. README는 선택 경계, 감지 실패 동작, 두 레이아웃의 정보
차이를 함께 설명한다.
