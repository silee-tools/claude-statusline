# GitHub 계정 세그먼트의 네 필드 캐시 해석 설계

## 한 줄 정의

셸 프롬프트가 남기는 계정 상태 캐시를 statusline 이 필드 단위로 해석해, 활성 GitHub 계정과
그 계정의 인증·한도 상태를 `gh@` 세그먼트 하나에 표시한다.

## 목표

- 캐시 파일이 담은 계정명, 상태, 대기 마감 시각을 각각 읽어 표시에 반영한다.
- 계정명, 라벨, 색을 소스에 넣지 않고 설정 파일에서 읽는 현재 계약을 유지한다.
- 상태 표시를 특정 계정에 한정하지 않고 활성 계정이 무엇이든 같은 규칙으로 적용한다.
- 렌더 경로는 POSIX sh 를 유지하고, 캐시를 읽는 데 드는 프로세스 생성을 늘리지 않는다.

## 비목표

- statusline 은 캐시를 쓰지 않는다. 갱신 책임은 셸 프롬프트에 둔다.
- `gh` 명령 호출과 네트워크 접근을 렌더 경로에 넣지 않는다.
- 캐시 파일의 형식을 statusline 쪽에서 새로 정의하지 않는다. 형식의 정본은 그 파일을 쓰는
  셸 프롬프트다.
- 캐시가 오래됐는지 판정해 표시를 바꾸지 않는다. 신선도 판정과 갱신은 셸 프롬프트가 맡는다.

## 입력 계약

캐시 경로는 `${XDG_DATA_HOME:-$HOME/.local/share}/gh-prompt-user` 다. 셸 프롬프트는 탭으로
구분한 네 필드 한 줄을 쓴다.

```text
v2	<계정명 또는 -> 	<상태>	<대기 마감 로컬 epoch 또는 0>
```

상태는 다섯 가지다. `ok` 는 계정이 정상이고, `rate_limited` 는 API 한도를 소진해 마감 시각까지
기다려야 하며, `auth_failed` 는 토큰이 불량하거나 인증이 만료됐고, `unknown` 은 조회나 판정에
실패했으며, `no_active` 는 활성 계정이 없다. `rate_limited` 만 네 번째 필드에 0 보다 큰 값을
두고, 나머지는 0 이다. 활성 계정이 없거나 계정을 확정하지 못한 경우 두 번째 필드는 `-` 다.

## 레코드 정규화

statusline 은 읽어 들인 한 줄을 다음 규칙으로 해석한다. 어떤 입력이 와도 렌더가 실패하지
않도록 모든 경우에 해석 결과를 정한다.

| 입력 | 계정명 | 상태 |
|---|---|---|
| 탭이 없는 한 줄 | 그 줄 전체 | `ok` |
| `v2` 로 시작하는 네 필드 | 두 번째 필드 | 세 번째 필드 |
| 네 필드이지만 첫 필드가 `v2` 가 아님 | 두 번째 필드 | `unknown` |
| 그 밖(필드 수 불일치, 빈 파일) | 없음 | `unknown` |

탭이 없는 한 줄을 계정명으로 받아들이는 규칙은 계정명만 기록하는 다른 프롬프트 구현을 위해
둔다. 이 플러그인은 특정 셸 설정에 묶이지 않으므로, 계정명 한 줄만 쓰는 사용자의 화면이 깨지지
않아야 한다.

첫 필드가 `v2` 가 아닌 네 필드 레코드를 따로 구분하지 않고 판정 불가로 묶는 이유는, 알 수 없는
형식의 상태 필드를 신뢰할 근거가 없기 때문이다. 계정명 자리에 있는 값은 살려서 어느 계정을
쓰는 중인지는 보여 준다.

캐시 파일이 아예 없으면 세그먼트를 통째로 생략한다. 셸 프롬프트를 쓰지 않는 환경에서 빈 표시가
남지 않게 하기 위해서다.

## 표시 계약

라벨은 설정 파일이 계정명에 대응시킨 값이고, 매핑에 없으면 계정명을 그대로 쓴다. 상태 표시는
계정을 가리지 않고 같은 규칙으로 붙인다.

계정명 유무를 먼저 가른다. 계정명이 없거나 `-` 이면 상태 `no_active` 는 `gh@---` 로, 그 밖의
모든 상태는 `gh@?` 로 표시하며 둘 다 회색이다. 이 규칙을 먼저 적용해야 계정명 자리가 비어 있는
손상 레코드가 `gh@-` 같은 표시로 새지 않는다.

계정명이 있으면 상태에 따라 다음과 같이 표시한다.

| 상태 | 표시 | 색 |
|---|---|---|
| `ok` | `gh@personal` | 설정 색, 매핑이 없으면 앰버 |
| `rate_limited`, 마감 전 | `gh@work⏳9m` | 라벨은 설정 색, `⏳9m` 은 노랑 |
| `rate_limited`, 마감 후 | `gh@work` | 설정 색 |
| `auth_failed` | `gh@work!` | 전체 빨강 |
| `unknown` | `gh@work?` | 전체 회색 |
| `no_active` | `gh@---` | 회색 |

상태 문자 앞에 공백을 넣지 않고, 모래시계와 분 단위 숫자 사이에도 공백을 넣지 않는다.

남은 시간은 마감 시각에서 렌더 시점을 뺀 초를 올림해 분으로 적는다. 1초가 남아도 `1m` 으로
보이고, 마감 시각에 도달하면 마커를 떼고 정상 라벨만 남긴다.

```text
남은 분 = (마감 epoch - 현재 epoch + 59) / 60의 정수 나눗셈
```

렌더 시점은 스크립트가 시작할 때 한 번 잡아 둔 값을 쓴다. 한 번의 렌더 안에서 여러 세그먼트가
서로 다른 시각을 보지 않게 하기 위해서다.

## 안전장치

캐시 파일과 설정 파일은 statusline 바깥에서 만들어지므로, 그 내용이 터미널 제어 문자를 주입하지
못하게 막는다. 네 번째 필드는 숫자만 허용하고 그렇지 않으면 마커를 붙이지 않는다. 색 코드도
숫자만 허용해 임의 이스케이프가 색 지정 자리에 들어가지 못하게 한다. 표시로 나가는 계정명과
라벨에서는 제어 문자를 제거한다.

## 설정 파일 계약

경로는 `${XDG_CONFIG_HOME:-$HOME/.config}/claude-statusline/gh-accounts` 이고 한 줄에 하나씩
`<계정명>=<라벨>,<256색 코드>` 를 적는다. `#` 로 시작하는 줄은 주석이다. 이 형식은 그대로
두므로 기존 설정 파일을 고칠 필요가 없다.

```text
octocat=personal,214
octodev=work,27
```

## 구현 방식

캐시는 셸 내장 `read` 로 읽어 네 필드를 한 번에 나눠 받는다.

```sh
IFS="$TAB" read -r ver login state deadline < "$cache"
```

파일 내용을 명령 치환으로 통째로 받아 문자열을 다시 자르는 방식은 쓰지 않는다. 필드 구분자인
탭이 제어 문자 제거 단계에서 사라져 네 필드가 한 덩어리로 붙기 때문이다. 내장 `read` 로 먼저
필드를 나누면 이 손실이 구조적으로 생기지 않고, 파일을 읽는 데 쓰던 별도 프로세스와 문자열
전체를 훑던 프로세스도 함께 없어진다.

## 테스트 전략

렌더 결과를 픽스처로 검증하는 기존 방식을 따른다. 계정 상태마다 캐시 픽스처를 만들어 상태 문자,
색, 라벨을 확인하고, 탭이 없는 한 줄과 필드 수가 어긋난 레코드도 각각 확인한다. 실패를 먼저
확인한 뒤 통과시킨다.

한도 상태의 마감 시각은 고정 숫자로 두지 않고 렌더 시점 기준의 상대값으로 만든다. 고정 숫자는
시간이 지나면 항상 마감 후로 판정돼 마커 검증이 조용히 무력해진다. 마감 직전과 마감 후를 모두
확인해 마커가 붙는 조건과 떨어지는 조건을 함께 고정한다.

## 결정과 근거

| 주제 | 선택지 | 결정 | 근거 |
|---|---|---|---|
| 상태 표시 대상 | 1) 모든 계정 / 2) 설정으로 지정한 계정만 | 1) 모든 계정 | 인증 실패와 판정 불가는 어느 계정에서든 같은 값을 가진다. 대상을 설정으로 가르면 설정 형식이 늘고 표시 규칙이 계정마다 달라진다. |
| 빈 캐시 파일의 표시 | 1) `gh@---` / 2) `gh@?` | 2) `gh@?` | 빈 파일은 활성 계정이 없다는 확인이 아니라 아직 판정하지 못한 상태다. 활성 계정 부재는 `no_active` 상태로 명시될 때만 `gh@---` 로 표시한다. |
| 형식을 모르는 네 필드 레코드 | 1) 계정명과 상태를 모두 버림 / 2) 계정명만 살림 | 2) 계정명만 살림 | 상태 필드는 의미를 확정할 수 없지만 계정명 자리의 값은 어느 계정을 쓰는지 알려 준다. |
| 캐시 신선도 판정 | 1) statusline 도 판정 / 2) 셸 프롬프트에 위임 | 2) 위임 | 판정을 양쪽에 두면 같은 캐시를 두 기준으로 해석하게 된다. 갱신을 실행하는 쪽이 신선도도 판정한다. |

## 배포

플러그인은 버전 고정 캐시에서 로드되므로 `claude-statusline/.claude-plugin/plugin.json` 과
`.claude-plugin/marketplace.json` 의 버전을 같은 값으로 올린다. README 의 캐시 형식 설명과 상태
표시 설명도 이 문서의 표시 계약에 맞춘다.
